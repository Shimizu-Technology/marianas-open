# Photo intake API (D4)

Contract for the admin client. All paths below are relative to `/api/v1`, require an authenticated **admin or staff** user, and scope every record to the event. Public gallery routes retain their existing shape. Errors use `{error:string}` or `{errors:string[]}`; invalid input is 422, missing event/record 404, missing authentication 401, insufficient role 403.

## Albums and settings

- `GET /admin/events/:event_id/gallery-albums` → `{albums:[{id,name,sort_order,count,cover_url}],settings:{timezone,hold_flagged}}`.
- `POST` same path, `{name}` → 201 `{album:{id,name,sort_order,count,cover_url}}`.
- `PATCH .../gallery-albums/:id`, `{name?,sort_order?}` → `{album:{...}}`. Rename atomically updates category strings; duplicate names are rejected. sort_order is a zero-based position; moving an album atomically shifts all intervening albums. Reorder changes public category ordering (images retain their own order). Count includes hidden/processing images; cover is the first active ready image with an available thumbnail.
- `PATCH .../gallery-albums/settings`, `{timezone?,hold_flagged?}` → `{settings:{timezone,hold_flagged}}`. Timezone must be an IANA identifier (e.g. `Pacific/Guam`, the explicit default). `hold_flagged` defaults false and affects subsequent review/import work, not already reviewed images. Import choices are snapshots.

Albums are first-class records, including empty albums. Existing category strings are preserved/backfilled; assigning a category through old APIs creates the corresponding album. No album delete is exposed. Public category JSON remains `{name,count}` and follows album sort order, followed by preset suggestions.

## Images (existing APIs, additive fields)

`GET /admin/events/:event_id/gallery-images/upload_policy` → `{upload_policy:{content_types:string[],extensions:string[],type_label:string}}`. This staff-only, event-scoped configuration reflects the API/worker native processor. Baseline formats are JPEG, PNG, WebP, GIF and TIFF; HEIC/HEIF/AVIF require `heifload`, probed once per process at boot. API and worker must use matching native libraries/revisions. The browser uses a baseline-only picker while this request loads or fails, then uses the reported policy. Unsupported direct uploads return 422 before creating a blob; multipart/completion model validation uses the same policy. iPhone photos upload as JPEG from the photo picker when HEIC/HEIF are omitted from `accept`; ZIP photos must be exported as JPEG when optional decoders are absent.

New uploads never derive title, caption, or alt text from filenames. Explicit staff text is preserved. original_filename and review/intake metadata are admin-only; public image JSON omits them. Without rewriting stored data, public serialization uses original_filename (or the attached blob filename when missing) and suppresses historical title/caption/alt text matching the filename, stem, or legacy stem with dashes/underscores replaced by spaces (case-insensitive); descriptive text is preserved.

`GET /admin/events/:event_id/gallery-images` retains pagination, `category`, `batch_id`, `status`, and response shape. Add `q` (case-insensitive literal filename substring, max 200 characters), `hidden=1` (inactive only), `needs_review=1` (nonempty flags and no `reviewed_at`). Filters combine with AND. Each image adds:

- `review_flags:string[]`: `low_sharpness`, `dark`, `overexposed`, `exact_duplicate`, `near_duplicate`.
- `reviewed_at:string|null` (UTC ISO timestamp), `captured_at:string|null` (UTC ISO timestamp), `capture_source:"exif"|"zip_mtime"|null`, `proposed_category:string|null`.

`PATCH .../gallery-images/bulk_update`, `{ids:number[],active?:boolean,category?:string|null,approve_review?:true}` retains `{updated:number}`. Approval sets `reviewed_at` and releases only review-held images; manually hidden images stay hidden. Explicit `active` takes precedence. Flags remain as provenance. Existing hide/show/move and `DELETE .../bulk_destroy` `{ids}` → `{deleted:number}` remain. Bulk selection is event-scoped; empty selections/unsupported updates are 422.

## ZIP imports

- `GET /admin/events/:event_id/gallery-imports` → `{imports:[{id,status,filename,total_entries,processed_entries,imported_count,skipped_count,errors:[],album_type,category,timezone,hold_flagged,created_at,completed_at}]}`; latest 25, statuses `queued|processing|completed|failed`. `errors` contains bounded `{entry,message}` records. `processed_entries` counts completed archive entries, including skipped metadata/nonimages; imported/skipped counts count files. Counters survive retries. System metadata files and nonimages increment skipped_count and add bounded reasons; directories only increment processed_entries. Completed may include skipped invalid images; unsafe archives fail. A corruption discovered after earlier valid entries were imported preserves those safe photos and their counters; structural/path attacks are rejected before any photo is imported.
- `POST .../gallery-imports/prepare_direct_upload`, `{filename,byte_size,checksum}` → `{signed_id,direct_upload:{url,headers}}` (same upload shape as images). Browser streams a ZIP directly to the configured Active Storage service. ZIP extension required; checksum is base64 MD5; size 1–4 GiB inclusive. The signed blob is bound to event and preparer. No multipart archive proxy endpoint.
- `POST .../gallery-imports`, `{signed_id,album_type,category?,timezone?,hold_flagged?}` → 202 `{import:{...}}`; retry with same blob returns 200 and original import, ignoring changed choices. `album_type` is any nonblank type up to 65 characters (including `Podium`, `Tournament`, `Opening Ceremony`, or a custom label). Omitting category defaults to album_type; an explicit blank string or null means Uncategorized (category null), while album_type is preserved for day proposals. Timezone/default hold setting comes from event settings. Staff should explicitly choose the event timezone before import. Enqueue is safe to repeat, including crash recovery; a recurring sweep re-enqueues queued/processing imports idle for 30 minutes every 10 minutes; workers serialize per event. Reuploading identical photos skips SHA-256 duplicates within the event and adds an `exact_duplicate` flag to the retained image. Different events remain independent.

Limits: compressed archive 4 GiB, 10,000 entries, individual extracted file 50 MiB (or lower configured image limit), total extracted bytes 8 GiB, per-file and archive compression ratio 100:1. Reject encryption, unsupported compression, absolute/drive/backslash/traversal paths, symlinks/special files, duplicate paths, corrupt headers/CRC/size discrepancies. Ignore directories, macOS metadata and nonimage files; baseline signatures are JPEG, PNG, WebP, GIF and TIFF; AVIF and HEIC/HEIF require the cached native `heifload` capability. Unsupported optional signatures are skipped before decoding and increment `skipped_count` with the JPEG export explanation in `errors`. Extension/MIME alone never authorize an image. Images have at most 60 million pixels, one frame/page, 1–4 channels and 8/16-bit unsigned samples. Native decoding remains bounded by this sample budget; provision worker RAM for worst-case ~480 MiB source samples plus library overhead. Decode failures are skipped with an error, never published.

Worker resources: preflight free TMPDIR space using df before download: declared archive bytes + max entry size + 512 MiB headroom. Refuse with a persisted actionable error when space is insufficient; ENOSPC terminates safely and temporary files are cleaned. A maximum-size ZIP needs at least 4 GiB + 50 MiB + 512 MiB free ephemeral space: small Render worker disks cannot accept it. Keep worker concurrency at 1, and size ephemeral storage accordingly. Stream archive download in chunks to a size-checked private temporary file; inspect the central directory before processing; stream one entry at a time into a size-checked temporary file and then storage. Maximum temporary disk is 4 GiB + 50 MiB per executing importer, without extracting paths. Import worker saves its analysis so the variant worker does not repeat review decoding. Memory holds bounded ZIP metadata, IO chunks, and a review thumbnail (256px); native decoding is bounded by the pixel limit. Run a single import worker/concurrency initially on the existing dedicated Solid Queue worker; no web-process extraction. ZIP64 supported. Archive blobs are detached/purged after terminal processing; failed blob uploads use the existing two-day unattached cleanup. No local filesystem source paths or public archive URLs are returned.

## Timestamps and proposals

EXIF `DateTimeOriginal` with a valid `OffsetTimeOriginal` is an instant; convert it to the chosen event timezone. Without an offset, interpret it as wall-clock time in that timezone; server timezone never participates. Only ZIP entry mtime is a fallback when EXIF is absent/invalid. Invalid/nonexistent/ambiguous DST local times produce no captured timestamp (no guessed offset); fallback may still resolve a valid ZIP time. No upload/created/modified-EXIF timestamp is substituted.

- `GET /admin/events/:event_id/gallery-day-proposals?album_type=Podium` → `{proposals:[{category,image_ids:number[],date:"YYYY-MM-DD"}],unassigned_count}`. Dates derive from captured timestamps in the selected capture timezone (event timezone for direct uploads). Day N is `(local_date - event.date) + 1`, only within `event.date..(event.end_date || event.date)`; missing days never renumber later days. Preview supports choosing any album_type: eligible candidates are that intake type in its original category, or direct photos that are uncategorized/in the selected type category. Optional `category` on GET and POST additionally admits direct photos in the currently selected source album, so staff can choose a different type (e.g. Stage → Opening Ceremony). Unassigned counts eligible images with missing/out-of-range timestamps. Manually moved images cease to be candidates. `proposed_category` is computed from these same current proposals, never silently applied.
- `POST` same path, `{album_type:"Podium",proposals:[{category,image_ids:number[]}]}` → `{updated:number}`. `album_type` may also be a query parameter. Apply requires album_type. Staff may confirm a nonempty subset, but every category/image pair must match the currently derived proposals. Duplicate IDs, foreign/stale IDs, arbitrary labels and empty proposals are rejected atomically with 422. Confirmation assigns category strings/albums and clears proposals for moved images. No category changes happen merely from uploading/reviewing.

## Review policy

The asynchronous review worker uses a bounded grayscale thumbnail: Laplacian variance < 35 → low_sharpness; > 80% pixels below 30 → dark; > 80% above 245 → overexposed. A 64-bit difference hash with Hamming distance ≤ 5 against event peers → near_duplicate (exact content hashes handled separately). These are advisory deterministic heuristics. Review never claims photographic quality certainty. Default is publish after successful variant generation; with hold_flagged enabled, flagged images are inactive until staff approval. Review/processing retries do not undo explicit staff approval or hide decisions. Existing single-image uploads also receive review; their capture source is EXIF only.
